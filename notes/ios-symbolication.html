學習筆記 · iOS crash log

把 .ips 變成看得懂的 logSymbolication

玩家閃退時 iPhone 留下的 .ips 只有一串記憶體位址。要知道是哪個函式、哪一行出事，得拿編譯時留下的對照表把位址翻回名字。這份筆記從「symbol 是什麼」講到 Unity 專案實際要注意的事。

01這個行為叫什麼

符號化Symbolication

把 crash report 裡的記憶體位址，透過 dSYM 對照回函式名稱、檔名和行號的過程。反過來說，還沒處理過的報告叫做「未符號化（unsymbolicated）」。

02Symbol 到底是什麼

電腦執行時只認「位址」，例如「跳到 0x104A3C2C0 開始執行」。函式名稱 SkillCaster.ApplyEffect() 是給人看的。Symbol（符號）就是「名字 ↔ 位址」這張對照表裡的每一筆紀錄。

原始碼的函式名像書裡的章節標題
機器碼的位址像頁碼
Symbol 表 / dSYM像書後的目錄：哪個標題在第幾頁

App 上架前，為了縮小檔案、也避免被逆向工程，會把這份目錄撕下來（strip），另外存成 .dSYM 檔。所以玩家手機上的 App 只剩頁碼，閃退時記下來的也只有頁碼。

03從編譯到閃退的整條路

.ips 和 dSYM 是在兩個地方分別產生的，要湊在一起才拼得回完整資訊。

04位址怎麼查回函式

iOS 有一個安全機制叫 ASLR：每次啟動 App，程式在記憶體裡的起點都會隨機換位置。所以不能直接拿閃退位址去查表，要先扣掉這次的載入起點，算出「從程式開頭算起的距離」，也就是偏移量（offset）。dSYM 記的就是偏移量。

0xA3C2F0 比 ApplyEffect 的起點 0xA3C2C0 大、比下一個函式 0xA3C400 小，所以閃退發生在 ApplyEffect 裡面。dSYM 另外還記錄了每段位址對應的行號，因此能精準指到第 88 行。

05前後對照

.ips 裡最重要的是 stack trace（呼叫堆疊）：一層層記錄「誰呼叫了誰」。由上往下讀，第 0 行是真正出事的地方，第 1 行是呼叫它的函式，以此類推。

符號化前 
#  模組              閃退位址       = 載入起點 + 偏移(十進位)
0  UnityFramework   0x104a3c2f0  0x104000000 + 10732272
1  UnityFramework   0x104a3c150  0x104000000 + 10731856
符號化後 
0  UnityFramework   SkillCaster_ApplyEffect_m8A2F  (SkillCaster.cs:88)
1  UnityFramework   SkillCaster_Cast_m3C11         (SkillCaster.cs:42)

讀法：Cast() 在第 42 行呼叫了 ApplyEffect()，ApplyEffect() 執行到第 88 行時崩潰。

06常用工具

Xcode最簡單

Window → Devices and Simulators → View Device Logs，把 .ips 拖進去。只要對應的 dSYM 在電腦上、Spotlight 搜得到，Xcode 會自動符號化。

atos手動查單一位址

就是第 04 節那張圖的指令版。-l 給載入起點，最後一個參數給閃退位址。

atos -arch arm64 \
  -o UnityFramework.framework.dSYM/Contents/Resources/DWARF/UnityFramework \
  -l 0x104000000 \
  0x104a3c2f0
Crashlytics 等線上收集

建置時自動上傳 dSYM，線上收到閃退就直接顯示符號化後的結果，不用自己對檔案。

07Unity 專案要注意的地方

  1. 找 UnityFramework 的 dSYM，不是主 App 的C# 經過 IL2CPP 後都編進 UnityFramework。dSYM 在 Xcode Organizer 的 Archive 裡：右鍵 Show in Finder → 顯示套件內容 → dSYMs。
  2. dSYM 必須和那一版 build 完全吻合每次編譯都有唯一 UUID，.ips 裡也記著。拿別版的 dSYM 會對不上，甚至對錯函式。每次定版上架都要把該版 dSYM 跟版本號一起歸檔。
  3. 函式名長得有點怪是正常的SkillCaster_ApplyEffect_m8A2F 是 IL2CPP 轉成 C++ 時產生的名字，前半段就是「類別_方法」，後面的亂碼可以忽略。
  4. 不是所有錯誤都要符號化C# 層丟出的例外（例如 NullReferenceException）在 Unity log 裡通常已有 C# stack trace。.ips 主要用在 native 層真的崩掉的時候，例如記憶體存取錯誤、被系統強制關閉。

08名詞小抄

.ips
iOS 的閃退報告檔，記錄當下每條執行緒的呼叫堆疊（位址）。
Symbol
符號。「函式名 ↔ 位址」對照表中的一筆紀錄。
Symbolication
符號化。把報告裡的位址翻回函式名、檔名、行號。
dSYM
debug symbol 檔。編譯時從 App 拆出來的對照表，要自己保存。
strip
把符號表從二進位裡移除，讓 App 變小、也較難被逆向。
UUID
每次 build 的唯一身分證，用來確認 dSYM 和 .ips 是同一版。
ASLR
每次啟動時隨機決定程式的載入起點，是 iOS 的安全機制。
Offset
偏移量。閃退位址減去載入起點，dSYM 用它來查表。
Stack trace
呼叫堆疊。一層層記錄「誰呼叫了誰」，第 0 行是出事點。
IL2CPP
Unity 把 C# 轉成 C++ 再編譯成原生碼的工具鏈。
atos
macOS 內建指令，輸入位址和 dSYM，回傳對應的函式與行號。
