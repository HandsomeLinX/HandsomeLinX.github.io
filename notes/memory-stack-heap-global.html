Stack / Heap / Global 記憶體複習

以 Unity App（IL2CPP）與 Unity WebGL 兩種載體對照

1. 三區概念2. C# 對照與誤區3. App vs WebGL4. GC 時機5. RPG H5 實務

1. 三區概念：記憶體地圖

Stack＝便條紙進函式疊一張，return 就撕掉，不需要 GC。容量小且固定，無限遞迴會 StackOverflowException。
Heap＝倉庫new 出來的 class 物件放這裡，生命週期不跟函式綁定，沒人引用後才由 GC 回收。會造成 GC 卡頓與碎片。
Global / static＝公告欄從程式啟動一直存在到結束，是 GC 的根（root）。

2. C# 對照與兩個常見誤區

class SkillCaster {
    static List<ItemData> items = new(); // items 這個「欄位」在 global，List 本體在 heap
    Vector3 spawnPos;                    // struct，但跟著 SkillCaster 物件放在 heap
    void Cast() {
        Vector3 tmp = spawnPos;          // 區域 struct → stack
        Monster m = new Monster();       // m（參考）在 stack，Monster 物件在 heap
        object o = 5;                    // boxing → heap 多一個垃圾
    }
}
  1. 值型別／參考型別不決定位置，「宣告在哪裡」才決定。struct 當區域變數在 stack，當 class 的欄位就跟著物件進 heap。
  2. static 欄位本身很小，但它是 GC root。被它指到的物件永遠不會被回收，是 Unity 記憶體洩漏最常見的來源（例如 static 字典一直累積 Sprite 參照）。

3. 兩種載體：Unity App vs WebGL

項目Unity App（IL2CPP）Unity WebGL
記憶體來源OS 行程虛擬記憶體，可歸還單一 ArrayBuffer，上限由 Maximum Memory Size 設定
Stack每條執行緒各一（主執行緒、Render、Job worker）只有一條，大小固定，深遞迴更容易爆
Heap 成長可增可減只長不縮；擴張需重新配置，瞬間尖峰最危險
GC 時機幀內也能觸發（可掃描 stack）只在幀與幀之間執行
資源載入直接讀進 native heap先在 JS heap，再複製進 WASM heap（短暫雙份）
超量後果被系統殺掉（iOS jetsam、Android LMK）配置失敗 OOM，或瀏覽器直接殺分頁

App 的重點：有兩種 heap

一張 Texture2D 在 managed heap 只是一個很小的 C# 外殼，像素資料在 native heap。texture = null 讓 C# 物件被 GC 收走，native 資料不一定會釋放，仍要 Destroy()、Resources.UnloadUnusedAssets() 或 AssetBundle.Unload()。

WebGL 的重點：所有東西都在同一個盒子裡

static、stack、native heap、managed heap 全部擠在同一塊 linear memory 裡。新版本上限可到 4GB，但手機瀏覽器實際能拿到的少很多；一次載入尖峰就會讓整塊記憶體停在高點。

4. 最反直覺的差異：GC 時機

原因：WASM 無法讓 GC 掃描執行中的 stack，不知道哪些物件還被區域變數抓著，只能等這一幀的函式都 return、stack 清空後才回收。

後果：同一幀內的垃圾會全部疊加。例如一次換地圖在同一幀裡解析大量 JSON、組字串、建立 List，App 可以中途回收，WebGL 會一路累積到撐破上限，觸發擴張甚至 OOM。

5. RPG H5 實務清單

  1. 怪物、技能特效、傷害數字一律用物件池，戰鬥過程中不要 new。
  2. 大計算拆到多幀處理（Coroutine 或分批），讓 GC 在中間有機會回收。
  3. 避免在 Update 裡組字串、用 LINQ、對 value type boxing。
  4. AssetBundle 載入後就 Unload(false) 掉 bundle 本體，降低 JS 與 WASM 雙份重疊的尖峰。
  5. Initial Memory Size 設在常態用量附近，減少執行中擴張；Maximum 不要無腦拉滿，否則手機瀏覽器會先拒絕。
跟工程師溝通的一句話：這個 OOM 是 managed 垃圾在同一幀累積，還是 native 資源（貼圖、AB）沒卸載？兩者修法完全不同，用 Memory Profiler 抓一次 snapshot 就能分辨。
